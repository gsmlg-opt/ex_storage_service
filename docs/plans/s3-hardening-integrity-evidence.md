## Scope and current implementation

- P1.3/P1.7: `Integrity`, `AwsChunked`, `Handlers.Shared`: state-threaded size/declaration/checksum validation before staging completion. SHA-256 payload, Content-MD5, CRC32, CRC32C, CRC64NVME, SHA1, SHA256 use independent expectations. Bounded control body default 1 MiB (callsite caps override); reader output remains bounded to 1 MiB reads. Final failures retain final Plug conn and abort LocalCAS staging.
- Accepted aws-chunked modes: authenticated `STREAMING-AWS4-HMAC-SHA256-PAYLOAD` with complete HMAC chunk/terminal chain, and `STREAMING-UNSIGNED-PAYLOAD-TRAILER` with required supported checksum trailer. Malformed framing, missing termination, decoded-length mismatch and post-terminal bytes fail. Unknown modes, including signed trailers, reject deliberately. No framing-only request acceptance. Low-level legacy framing utility remains for explicit framing tests, and is no longer the request verifier.
- `SigV4`: raw duplicate query pairs, RFC3986 plus/space encoding, per-segment percent encoding without slash/dot normalization, combined duplicate signed headers, signing scope/date/service/header validation; verified seed signing context feeds chunk checks.
- `Presigned`: encoded keys, actual custom signed header binding, raw pair canonicalization, duplicate auth fields rejected, scope/date/service/expiry/future-time checks; identity and IAM checks remain in router/authorization owned by other workers.
- `Shared`: bodyless HEAD errors, sanitized public errors, integrity status mappings, nested metadata/stage precondition status mappings.
- Multipart completion XML uses `read_full_body(conn, cap, verify_wire_checksums: false)` only for final-object checksum declarations, which require separate completion-result verification. Payload SHA and Content-MD5 remain checked. This does not prove multipart result checksum acceptance.
- Gateway PUT: LocalCAS validated disk spool before upstream mutation; `CloudCache.Client.put_file` uses 64 KiB file source, explicit Content-Length, precomputed signing hash and metadata/system headers; raw gzip preserved, only aws-chunked transfer encoding removed. Existing GET buffering has not been changed by this worker.
- `CloudCache.WriteThrough`: durable prepared journal before PUT; uncertain outcomes retain stage and remain unresolved; upstream success/local failure stays recoverable. Bounded `reconcile_page/3` requires matching independent HEAD operation/hash/length markers and only repairs local state. No external PUT retry. Startup/operator integration remains parent-owned.
- `LocalStore.put_file`: complete temporary-file copy and rename before cache index publication; existing per-bucket cache-index map is unchanged and is not claimed as bounded metadata work.
