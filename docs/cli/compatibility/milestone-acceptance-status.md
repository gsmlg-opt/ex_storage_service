# Milestone acceptance status

Audit baseline: `main` at `9b8661e58107eddb24cb8f15495cee4ac979219a`, plus the implementation diff. References are AWS CLI 2.31.18 and mc `77f82e18b5401a65958f1619df6ebb994634bd88`. This is an acceptance-gap audit, not a completed checklist or final release report. Individual reports record scoped runs; the coordinating integration run and provider report supersede historical counts only when actually executed.

The evidence overlay links implemented machinery to real source/tests. `implemented-unverified` means the code path exists, with exactly the stated evidence boundary. Generic catalog loading, flag discovery, shape validation and REST-XML binding do not verify all effects of an operation/member. No inventory requirement is blanket-marked `verified`; live provider absence is not client unsupported. Provider results must name their actual provider/version, prefix, commands, result and cleanup separately.

## Reproducing this inventory audit

Run from the repository root:

```sh
PAGER=cat python3 scripts/cli_compatibility/generate.py
PAGER=cat python3 scripts/cli_compatibility/generate.py --check
PAGER=cat python3 -m unittest discover -s scripts/cli_compatibility -p 'test_*.py'
```

Native grammar was inspected from the actual compiled `CLI.Registry.commands/1` and `globals/1`, without loading credentials, contacting providers or changing application state. The exact missing spellings table compares those runtime maps with locked mc source definitions. Matching spellings intentionally remain insufficient to establish matching behavior.
