# Retry and regional correction evidence

AWS CLI 2.31.18 defaults to `standard` retry mode and three total attempts. Its bundled `botocore/configprovider.py`, `config.py`, and `client.py` support only `standard` and `adaptive`: `legacy` is rejected before sending a request. This differs from older Botocore releases. Resolved shared-profile/environment values flow through `Retry.options/2`; explicit call options win. Each attempt invokes the caller again so transport integration refreshes credentials, re-encodes replayable sources and signs a new request.

`test/fixtures/s3/retry-wire.json` records actual pinned Linux executable calls to an isolated loopback HTTP fixture on 2026-10-15. Dummy credentials were used; no authentication values are retained. It proves three default SlowDown attempts, one with `AWS_MAX_ATTEMPTS=1`, no retry for a bare HTTP 429, three attempts for a parsed SlowDown at HTTP 429, legacy-mode rejection with zero requests, and custom-endpoint HeadBucket region correction from us-east-1 to us-west-2 without changing the endpoint. The retry-count cases are consumed by the scoped regression tests.

Standard/adaptive retries share an invocation-owned 500-token retry quota. Ordinary retries cost five tokens, transport timeout retries cost ten, and successful calls replenish one token or their final retry cost. Adaptive mode adds the pinned measured-rate smoothing, CUBIC rate update, and token bucket; rate limiting enables after the first modeled throttling response. Waiting occurs outside the state server, checks the invocation coordinator at most every 50 ms, and respects cancellation plus the remaining overall deadline. An optional injected clock/sleeper makes policy tests deterministic. Shared state monitors its owner and stores no request or credential data. Multipart abort cleanup remains admissible after cancellation.

The design's replay safety intentionally limits retries beyond the reference: nonreplayable streams are never repeated, and uncertain mutations that can create versions or delete markers produce `outcome_indeterminate`. Read/List/Head operations and replayable multipart UploadPart/ListParts/Abort requests can retry eligible transient failures. Authentication and authorization failures stop. Standard backoff applies full jitter with a one-second initial range and caps the randomized result at twenty seconds. HTTP deadlines are supplied to each request; transport integration owns enforcing per-attempt connect/read limits.

Regional correction accepts a single well-formed bucket region from a qualifying service response, or a parsed error Region fallback. It rejects cross-partition corrections, ARN buckets, nonreplayable bodies, repeated corrections, ambiguous headers and unchanged/malformed regions. Endpoint rules validate a new immutable region context and retain the original custom endpoint policy, FIPS/dualstack settings and TLS configuration. The caller must rebuild authentication; no old signed request or response Location participates. When both the header and error Region are absent, Client performs at most one HeadBucket discovery on the original endpoint, without following Location. The failed request is drained and its lease released first, so a one-request coordinator cannot deadlock. Discovery strips object bodies/stream options, preserves TLS and the remaining deadline, and suppresses recursive discovery/correction. A validated, bounded 128-entry invocation cache keys endpoint, addressing style, initial region and bucket; subsequent calls use the cached region and freshly sign. AccessDenied never probes. Ambiguous duplicate region headers are rejected.

Scoped retry, region and provider-validation tests include actual HTTP Client integration. The client_region_test.exs suite has seven regional correction/discovery/cache cases, including a real delayed peer for the overall deadline. Two regressions first reproduced a lost corrected region without invocation state and a second correction after a transient retry. Retry now supplies its effective owned state to the client callback, and a call-local counter keeps the one-correction budget across all attempts. The pinned redirector's `s3_redirect.redirected` marker has the same call lifetime. The focused retry/region suites passed 28 tests after the repair. Integration proves fresh regional signatures on the original custom endpoint under a single request lease, effective retry settings, Location non-forwarding, cancellation during backoff, and zero remaining leases. Actual live AWS throttling, concurrent adaptive scheduling differential traces, cross-platform runtime execution, and top-level region-correction executable acceptance remain separate integration checks; this document does not claim full retry/endpoint parity.

AWS frontend errors now retain the sanitized service message separately from native diagnostics. Retry exhaustion metadata drives the pinned AWS plain stderr spelling; high-level transfer/preflight failures return status 1, while modeled s3api service errors return 254. The executable differential captures a HEAD 403 with AWS_MAX_ATTEMPTS=1 and verifies exact fatal text/status without ANSI output.
